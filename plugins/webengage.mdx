The WebEngage connector adds WhatsApp and RCS as sendable channels inside WebEngage. Campaigns
are built and triggered in WebEngage; the connector translates each payload into a OneXtel
message and returns delivery status.

<Info>
**Two versions of this connector exist.** The setup below is **V1**, live today. **V2** is a
native rebuild that is being brought live — same WebEngage-side configuration, new delivery-report
flow, SMS on the same host, and more. See [V2 — coming live](#v2--coming-live) before you start a
new integration.
</Info>

## V2 — coming live

<Warning>
V2 is not yet accepting production traffic. The endpoints below are fixed and UAT access is
available on request from omni.tech@onextel.com; do not repoint a live V1 configuration until
OneXtel confirms your account has been moved.
</Warning>

V2 replaces the connector behind `we.onexaura.com` with OneXtel's native build. What you gain:

- **Delivery reports relayed with mapped error codes.** OneXtel's delivery callbacks go to the
  connector, which converts each into a WebEngage Delivery Status Notification with the Meta,
  RCS-operator or OneXtel failure code mapped onto WebEngage's own status-code table, and the
  original code kept in the `reason` field. In V1 you register WebEngage's webhook directly at
  OneXtel and the codes arrive unmapped.
- **Lower delivery latency.** Sends go to OneXtel's regional host directly — Indian numbers to
  `api.onexaura.com`, all other numbers to `api.onexglobal.ae` — with no intermediate hop.
- **Higher throughput.** Each connector instance is stateless, so OneXtel scales it horizontally
  to the TPS your account is provisioned for.
- **More template types.** WhatsApp text, image, video, document and carousel templates with
  quick-reply, URL, dynamic-URL and copy-code buttons; RCS text, rich card and rich carousel.
- **SMS on the same host.** The WebEngage SMS connector, with its own delivery-report mapping,
  moves next to WhatsApp and RCS under `we.onexaura.com`.
- **Listed natively in WebEngage.** OneXtel appears as a named provider in WebEngage's channel
  setup, so the endpoint and headers no longer have to be typed into a Private WSP / RSP form.
  Until that listing is live, the Private WSP / RSP steps in V1 work unchanged with the V2 URLs.

### V2 endpoints

All on `https://we.onexaura.com`. Send routes take the OneXtel API key in an `apikey` header, or
as `?apikey=` on the URL if the WebEngage form cannot set headers.

| Purpose | Direction | URL |
| --- | --- | --- |
| WhatsApp send | WebEngage → connector | `https://we.onexaura.com/webengage/whatsapp/send` |
| RCS send | WebEngage → connector | `https://we.onexaura.com/webengage/rcs/send` |
| SMS send | WebEngage → connector | `https://we.onexaura.com/api/we` |
| WhatsApp delivery reports | OneXtel → connector → WebEngage | `https://we.onexaura.com/webengage/whatsapp/dlr` |
| RCS delivery reports | OneXtel → connector → WebEngage | `https://we.onexaura.com/webengage/rcs/dlr` |
| Health check | — | `https://we.onexaura.com/webengage/health` |

Append `/in`, `/ksa` or `/us` to a delivery-report URL to pin the WebEngage data centre the DSN is
sent to; without it the connector uses the region on file for your account.

### What changes in the setup

The WebEngage side is the same as V1: a Private WSP or RSP configuration pointing at the send
URL, with the `apikey` header (and `campaigntype` for RCS), and a template that replicates the
OneXtel one. Two steps on the OneXtel side change:

<Steps>
  <Step title="Register the connector, not WebEngage, as the OneXtel callback">
    In the OneXtel portal, go to **Configuration → Add New Callback** and register the
    delivery-report URL above for the channel — `…/webengage/whatsapp/dlr` for WhatsApp,
    `…/webengage/rcs/dlr` for RCS — against the API key used for sending. Method `POST`, no
    extra headers. In V1 this is where you pasted WebEngage's webhook URL; in V2 that URL is
    configured on the connector instead.
  </Step>
  <Step title="Hand the WebEngage callback tokens to OneXtel">
    Send omni.tech@onextel.com the WebEngage callback token for each channel and data centre
    you use (WhatsApp and RCS tokens are separate from the SMS token). OneXtel configures them
    on the connector; nothing is forwarded to WebEngage until they are in place.
  </Step>
</Steps>

### What WebEngage receives

One DSN per delivery event, in WebEngage's Private WSP format, sent to WebEngage's tracking
endpoint for your data centre with your callback token:

```json
{
  "version": "1.0",
  "messageId": "ed70a6d4-431c-4d18-a062-a4d0a6c68153",
  "toNumber": "919999999999",
  "status": "whatsapp_failed",
  "statusCode": 2009,
  "reason": "Message undeliverable — recipient not on WhatsApp or has not accepted terms [onextel=131026]",
  "timestamp": "2026-09-10T07:21:03+0000"
}
```

`messageId` is the one WebEngage sent, carried through OneXtel as `custref1`. `sent`,
`delivered` and `read` map to `whatsapp_sent`, `whatsapp_delivered` and `whatsapp_read` with
`statusCode` 0. A failure maps as follows; anything not listed becomes `9988` with the raw code
in `reason`.

| OneXtel / Meta code | Meaning | WebEngage code |
| --- | --- | --- |
| 131026 | Recipient not on WhatsApp | 2009 not delivered |
| 131047 | Outside the 24-hour window | 2024 not opted in |
| 131049, 900115, 900120, 900121 | Meta or account frequency caps | 2026 frequency cap |
| 131050, 4013, 900122 | Opted out or blacklisted | 2006 user blocked |
| 132001, 4001, 134102 | Template missing or unapproved | 2021 template missing |
| 132000, 132012, 132018, 4018 | Template parameter mismatch | 2022 parameter mismatch |
| 132015, 132016, 900118, 900119 | Template paused, disabled or category blocked | 2023 template did not match |
| 4, 80007, 130429, 131056, 131016, 900117 | Rate limits and temporary outages | 2015 throttled |
| 4010, 131042 | Credit or payment | 2000 insufficient credit |
| 0, 190 | Token expired | 2011 authentication failure |
| 10, 200–299, 368, 131031, 4022 | Permission or account restriction | 2005 authorization failure |

RCS events map the same way with an `rcs_` prefix: `rcs_sent`, `rcs_delivered`, `rcs_read`,
`rcs_failed`. Operator failures are classified from the operator's own wording — invalid or
non-RCS number 2003, DND or opt-out 2006, expired 2008, throttled 2015, template rejected 2023,
otherwise 2009 — because Jio and Vi reuse the same numeric codes for different conditions
(see [RCS operator error codes](/api-reference/rcs/error-codes)). SMS delivery reports follow the
[India](/api-reference/sms/error-codes) and
[international](/api-reference/sms-international/error-codes) code tables.

### V2 limitations

- Inbound messages are still not supported on WhatsApp and RCS.
- `LOCATION` WhatsApp templates are not accepted by the send route.
- WebEngage has not published an RCS delivery-status contract; the `rcs_` status words above are
  OneXtel's and can be changed on the connector if WebEngage specifies others.

## Set up WhatsApp (V1)

<Steps>
  <Step title="Get your OneXtel API key">
    Log in to OneXtel, go to the **API** section, and click **Show API Key**. If no key
    exists, click **Generate API Key**. Copy it.
  </Step>
  <Step title="Open the WhatsApp integration">
    In WebEngage, go to **Data Platform → Integrations**, scroll down, and click
    **WhatsApp Setup (Configure)**.
  </Step>
  <Step title="Configure a Private WSP">
    Scroll down and click **Private WSP**, then fill in the configuration popup:

    | Field | Value |
    | --- | --- |
    | Configuration Name | Any name you choose |
    | WABA Number | Your WhatsApp Business Account number |
    | URL | `https://we.onexaura.com/webengage/whatsapp/send` |
    | Request Type | **Send personalization variables** |

    Add a custom header with the key `apikey` and your OneXtel API key as the value. Copy and
    paste the key rather than typing it. Save the configuration.
  </Step>
  <Step title="Copy the webhook URL">
    Find your configured Private WSP, click the three-dot menu next to it, and select
    **View Webhook URL**. Copy the URL.
  </Step>
  <Step title="Register the callback in OneXtel">
    In the OneXtel portal, go to **Configuration → Add New Callback** and register the webhook
    URL against the same API key, with the channel set to `WhatsApp`.
  </Step>
  <Step title="Create a matching template">
    On the WhatsApp integration page, scroll to the **Template** section and create a template
    that replicates one already approved in your OneXtel instance. Save it.
  </Step>
</Steps>

## Set up RCS (V1)

<Steps>
  <Step title="Get your OneXtel API key">
    As above — **API → Show API Key** in the OneXtel portal.
  </Step>
  <Step title="Open the RCS integration">
    In WebEngage, go to **Data Platform → Integrations**, scroll down, and click
    **RCS Setup (Configure)**.
  </Step>
  <Step title="Configure a Private RSP">
    Scroll down and click **Private RSP**, then fill in the configuration popup:

    | Field | Value |
    | --- | --- |
    | Configuration Name | Any name you choose |
    | RCS Business number | Your sender profile name |
    | URL | `https://we.onexaura.com/webengage/rcs/send` |

    Add two custom headers:

    | Header key | Value |
    | --- | --- |
    | `apikey` | Your OneXtel API key |
    | `campaigntype` | `Promotional` or `Transactional` |

    Save the configuration.
  </Step>
  <Step title="Copy the webhook URL">
    Find your configured Private RSP, click the three-dot menu, and select
    **View Webhook URL**. Copy the URL.
  </Step>
  <Step title="Register the callback in OneXtel">
    In the OneXtel portal, go to **Configuration → Add New Callback** and register the webhook
    URL against the same API key, with the channel set to `RCS`. See
    [RCS delivery notification](/api-reference/rcs/callback-delivery-notification).
  </Step>
  <Step title="Create a matching template">
    On the RCS integration page, scroll to the template section and create a template that
    replicates one already approved in your OneXtel instance. Save it.
  </Step>
</Steps>

<Note>
Because `campaigntype` is set on the configuration rather than per message, you need a separate
Private RSP configuration for each RCS message type you intend to send.
</Note>

## Create a campaign

<Steps>
  <Step title="Start the campaign">
    Go to the **Channels** tab, select **WhatsApp** or **RCS**, and create a new campaign.
    Complete the campaign configuration and choose your target user segment.
  </Step>
  <Step title="Select the template">
    In the **Message** tab, select the template you created and fill in its variables.
  </Step>
  <Step title="Tag the campaign">
    Under **Custom Key–Value Pairs**, add the key `campaignName` with a campaign identifier as
    the value. This is what lets you filter the campaign's data in OneXtel reporting — without
    it, sends are harder to attribute.
  </Step>
  <Step title="Add optional metadata">
    Optionally add `custref3`, `custref4`, and `custref5` as further key-value pairs to carry
    your own identifiers through to OneXtel.
  </Step>
  <Step title="Test before going live">
    Run a test send and confirm the message renders correctly before triggering the live
    campaign.
  </Step>
</Steps>

## Requirements

- A WebEngage account with the WhatsApp channel enabled.
- A OneXtel account with the relevant channels enabled.
- Pre-approved templates in OneXtel — WebEngage templates must replicate an already-approved
  OneXtel template. See [RCS templates](/api-reference/rcs/templates) and
  [WhatsApp templates](/api-reference/whatsapp/templates-create).
- **A WebEngage OAuth token for the webhook**, which you obtain from WebEngage directly.
  OneXtel cannot issue it on your behalf.

## Limitations

### Both channels

- **Inbound messages are not supported.** WebEngage cannot receive inbound messages on these
  channels, so customer replies will not appear in WebEngage. If two-way conversation matters,
  use the [WhatsApp](/api-reference/whatsapp/overview) or
  [RCS](/api-reference/rcs/overview) APIs directly.
- **Variable names must match the keys in the message payload.**
- **Callbacks time out after 5 seconds** and are retried up to three times. If WebEngage does
  not acknowledge within that window, the callback is dropped rather than queued for later
  redelivery.
- **Templates are duplicated, not synced.** A template created in WebEngage must manually
  replicate one approved in OneXtel. If either copy is edited, they drift apart.

### WhatsApp

- **Personalisation variables only.** This version of the connector supports personalisation
  variables and no other variable form.
- **Variable ordering is assigned by the connector.** WebEngage does not send a variable index,
  so the connector assigns positions when building the OneXtel payload. Verify order-sensitive
  templates with a test send before going live.

### RCS

- **Only template names and parameters are passed** to OneXtel — the template body itself is
  resolved on the OneXtel side.
