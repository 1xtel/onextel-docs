OneXtel adds WhatsApp, RCS and SMS as sendable channels inside WebEngage. Campaigns are built and
triggered in WebEngage. WhatsApp and RCS sends go through the OneXtel connector, which translates
each payload into a OneXtel message; SMS goes straight to OneXtel's own WebEngage endpoint. On the
way back, the connector turns every OneXtel delivery report into a WebEngage Delivery Status
Notification (DSN), with OneXtel's code mapped onto WebEngage's status-code table.

<Tip>
**Pick your channel once.** The sections below have **WhatsApp**, **RCS** and **SMS** tabs.
Choosing a tab in any section switches every section on the page to that channel.
</Tip>

## Before you start

- A WebEngage account with the channels you intend to use enabled.
- A OneXtel account with those channels enabled, and an API key — see
  [API keys](/guides/platform/api-keys).
- Pre-approved templates in OneXtel. WhatsApp and RCS templates in WebEngage must replicate an
  approved OneXtel template — see [RCS templates](/api-reference/rcs/templates) and
  [WhatsApp templates](/api-reference/whatsapp/templates-create). SMS templates must be
  DLT-registered — see [DLT registration](/guides/sms/dlt).
- **The WebEngage tokens for delivery reports**, which WebEngage issues per channel and data
  centre. OneXtel cannot issue them on your behalf.
- **Your WebEngage data centre** — India, KSA or US. Delivery reports must go to the data centre
  your account lives in.

### Connector endpoints

| Channel | Purpose | Direction | URL |
| --- | --- | --- | --- |
| WhatsApp | Send | WebEngage → connector | `https://we.onexaura.com/webengage/whatsapp/send` |
| WhatsApp | Delivery reports | OneXtel → connector → WebEngage | `https://we.onexaura.com/webengage/whatsapp/dlr/<dc>` |
| RCS | Send | WebEngage → connector | `https://we.onexaura.com/webengage/rcs/send` |
| RCS | Delivery reports | OneXtel → connector → WebEngage | `https://we.onexaura.com/webengage/rcs/dlr/<dc>` |
| SMS | Send | WebEngage → OneXtel | `https://api.onexaura.com/api/we/` |
| SMS | Delivery reports | OneXtel → connector → WebEngage | `https://we.onexaura.com/webengage/sms/dlr/<dc>` |
| — | Health check | — | `https://we.onexaura.com/webengage/health` |

Replace `<dc>` with your WebEngage data centre — `in`, `ksa` or `us`. It decides where the
connector sends each report, so it must match your account.

<Warning>
**The SMS send URL is on a different host and ends in a slash.** SMS goes to OneXtel's own
endpoint, `api.onexaura.com`, not to the connector — and without the trailing `/` it answers with
an error. Copy it exactly.
</Warning>

<Note>
**Never save a OneXtel callback with an empty header row.** OneXtel then sends a header with no
name, and the connector's web server refuses the whole request. If the callback form insists on
a header, add one named `callback` with the callback URL as its value — the connector ignores it.
</Note>

## Set up

<Tabs>
<Tab title="WhatsApp">

<Steps>
  <Step title="Get your OneXtel API key">
    Log in to OneXtel, go to the **API** section, and click **Show API Key**. If no key
    exists, click **Generate API Key**. Copy it.
  </Step>
  <Step title="Open the WhatsApp integration">
    In WebEngage, go to **Data Platform → Integrations**, scroll down, and click
    **WhatsApp Setup (Configure)**.
  </Step>
  <Step title="Configure a Private WSP">
    Scroll down and click **Private WSP**, then fill in the configuration popup:

    | Field | Value |
    | --- | --- |
    | Configuration Name | Any name you choose |
    | WABA Number | Your registered WhatsApp **business phone number**, with the country code — for example `919999999999`. Not the WABA ID |
    | URL | `https://we.onexaura.com/webengage/whatsapp/send` |
    | Request Type | **Send personalization variables** |

    Add a custom header with the key `apikey` and your OneXtel API key as the value. Copy and
    paste the key rather than typing it. Save the configuration.

    <Note>
    The connector also accepts the key as `Authorization: Bearer <key>`, or as `?apikey=` on the
    URL if a form cannot set headers.
    </Note>

    <Warning>
    **Use the phone number, not the WABA ID.** OneXtel finds your WhatsApp account from the
    business number. A WABA ID in this field is rejected as an invalid sender, which WebEngage
    shows as `2004`.
    </Warning>
  </Step>
  <Step title="Register the delivery callback in OneXtel">
    In the OneXtel portal, go to **Configuration → Add New Callback** and add a callback against
    the same API key:

    | Field | Value |
    | --- | --- |
    | Channel | `WhatsApp` |
    | Type | `Delivery Notification` |
    | HTTP Method | `POST` |
    | Callback URL | `https://we.onexaura.com/webengage/whatsapp/dlr/<dc>` — `in`, `ksa` or `us` |

    The connector maps each report and forwards it to WebEngage's tracking endpoint for that
    data centre.
  </Step>
  <Step title="Hand the WebEngage WhatsApp token to OneXtel">
    Send [omni.tech@onextel.com](mailto:omni.tech@onextel.com) the WhatsApp delivery-report
    token WebEngage issued for your account and data centre. OneXtel configures it on the
    connector. WebEngage refuses WhatsApp reports without it, so nothing reaches WebEngage until
    it is in place.
  </Step>
  <Step title="Create a matching template">
    On the WhatsApp integration page, scroll to the **Template** section and create a template
    that replicates one already approved in your OneXtel instance — same name, language, type
    and number of variables. Save it.
  </Step>
  <Step title="Create the campaign">
    Go to the **Channels** tab, select **WhatsApp**, and create a new campaign. In the
    **Message** tab, select the template and fill in its variables. Under **Custom Key–Value
    Pairs**, add `campaignName` with a campaign identifier, so the campaign can be filtered in
    OneXtel reporting. Optionally add `custref3`, `custref4` and `custref5` to carry your own
    identifiers through to OneXtel.
  </Step>
  <Step title="Test before going live">
    Run a test send and confirm the message renders correctly, and that its delivery status
    appears in WebEngage, before triggering the live campaign.
  </Step>
</Steps>

<Note>
If your account was set up with **WebEngage's webhook registered directly at OneXtel**, reports
still arrive, but with OneXtel's raw codes rather than WebEngage's. Change that callback's URL
to the connector's, as above, to get mapped codes.
</Note>

</Tab>

  </Step>
  <Step title="Open the RCS integration">

  </Step>
  <Step title="Configure a Private RSP">

    | Field | Value |
    | --- | --- |
    | Configuration Name | Any name you choose |
    | RCS Business number | Your sender profile name |
    | URL | `https://we.onexaura.com/webengage/rcs/send` |

    Add two custom headers:

    | Header key | Value |
    | --- | --- |
    | `apikey` | Your OneXtel API key |
    | `campaigntype` | `Promotional` or `Transactional` |

    <Note>
    Because `campaigntype` is set on the configuration rather than per message, you need a

    </Note>
  </Step>
  <Step title="Register the delivery callback in OneXtel">
    In the OneXtel portal, go to **Configuration → Add New Callback** and add a callback against
    the same API key:

    | Field | Value |
    | --- | --- |
    | Channel | `RCS` |
    | Type | `Delivery Notification` |
    | HTTP Method | `POST` |
    | Callback URL | `https://we.onexaura.com/webengage/rcs/dlr/<dc>` — `in`, `ksa` or `us` |

    See [RCS delivery notification](/api-reference/rcs/callback-delivery-notification) for what
    OneXtel sends.
  </Step>
  <Step title="Hand the WebEngage RCS token to OneXtel">
    Send [omni.tech@onextel.com](mailto:omni.tech@onextel.com) the RCS delivery-report token

    the connector.
  </Step>
  <Step title="Create a matching template">
    On the RCS integration page, scroll to the template section and create a template that
    replicates one already approved in your OneXtel instance. Save it.
  </Step>
  <Step title="Create the campaign">
    Go to the **Channels** tab, select **RCS**, and create a new campaign. In the **Message**
    tab, select the template and fill in its variables. Under **Custom Key–Value Pairs**, add
    `campaignName` with a campaign identifier, so the campaign can be filtered in OneXtel
    reporting. Optionally add `customRef3`, `customRef4` and `customRef5` to carry your own
    identifiers through to OneXtel.
  </Step>
  <Step title="Test before going live">
    Run a test send and confirm the message renders correctly, and that its delivery status
    appears in WebEngage, before triggering the live campaign.
  </Step>
</Steps>

</Tab>
<Tab title="SMS">

SMS sends go from WebEngage straight to OneXtel's own WebEngage endpoint, which accepts
WebEngage's payload as it is — India DLT fields included. The connector's only part is the return
leg: it maps each OneXtel delivery report onto WebEngage's SMS codes and forwards it.

| Part | What you do | Where |
| --- | --- | --- |
| [A](#part-a--add-onextel-as-a-private-ssp) | Add OneXtel as a Private SSP and set the DLT fields | WebEngage |
| [B](#part-b--register-the-sms-delivery-callback) | Register the delivery callback | OneXtel |
| [C](#part-c--hand-over-the-webengage-sms-token) | Hand over the WebEngage SMS token | OneXtel support |
| [D](#part-d--create-the-campaign-and-test-it) | Create the campaign and test it | WebEngage |

### Part A — Add OneXtel as a Private SSP

<Steps>
  <Step title="Get your OneXtel API key">
    In the OneXtel portal, go to **API** and click **Show API Key**. Use the key your DLT
    sender and templates are registered under.
  </Step>
  <Step title="Open the SMS integration">
    In WebEngage, go to **Data Platform → Integrations → SMS Setup**, and select
    **Private SSP** from the list of available SSPs.
  </Step>
  <Step title="Configure the Private SSP">
    | Field | Value |
    | --- | --- |
    | SSP Name | Any name you choose |
    | URL | `https://api.onexaura.com/api/we/` — keep the trailing `/` |

    Add a custom header:

    | Header key | Value |
    | --- | --- |
    | `Authorization` | `Bearer <your OneXtel API key>` |

    Save the configuration.
  </Step>
  <Step title="Set the India DLT details">
    In WebEngage's India DLT settings, enter your **principal entity ID**, and set each
    template's **DLT template ID**. Add your **telemarketer ID** too if your route needs one.
    WebEngage then sends every SMS with the DLT fields OneXtel needs.

    Store recipient numbers in WebEngage with the country code — `91XXXXXXXXXX`.
  </Step>
</Steps>

### Part B — Register the SMS delivery callback

In the OneXtel portal, go to **Configuration → Add New Callback** and add a callback against the
**same API key** you put on the Private SSP:

| Field | Value |
| --- | --- |
| Channel | `SMS` |
| Type | `Delivery Notification` |
| HTTP Method | `POST` |
| Callback Format | `WebEngage` |
| Callback URL | `https://we.onexaura.com/webengage/sms/dlr/<dc>` — `in`, `ksa` or `us` |

<Warning>
**The URL suffix is the only way the connector learns your data centre for SMS.** Without it,
reports go to the India data centre. A `region` header on this callback is not read.
</Warning>

### Part C — Hand over the WebEngage SMS token

Send [omni.tech@onextel.com](mailto:omni.tech@onextel.com) the SMS delivery-report token
WebEngage issued for your account and data centre. OneXtel configures it on the connector, and
reports for your data centre are held back until it is in place.

### Part D — Create the campaign and test it

<Steps>
  <Step title="Create the campaign">
    Go to the **Channels** tab, select **SMS**, and create a campaign against the Private SSP
    from Part A. Write the message exactly as registered on DLT, and pick the template that
    carries its DLT template ID.
  </Step>
  <Step title="Send a test">
    Send to a device you control and confirm the SMS arrives.
  </Step>
  <Step title="Confirm the delivery report">
    The message shows as sent in WebEngage's campaign report. A failure shows with a WebEngage
    code — see [Error code mapping](#error-code-mapping).
  </Step>
</Steps>

</Tab>

## Error code mapping

Every report the connector forwards carries a WebEngage `statusCode`. Failures also carry a
`message` (WhatsApp and RCS call it `reason`) that ends with OneXtel's original code — for
example `[onextel=131026]` — so the raw value is never lost.

<Tabs>
<Tab title="WhatsApp">

**Delivery reports**

`sent`, `delivered` and `read` are forwarded as `whatsapp_sent`, `whatsapp_delivered` and
`whatsapp_read` with code `0`. A failure is forwarded as `whatsapp_failed` with the code below.

| `2000` | Insufficient credit balance | `4010`, `131042`, `134011` |

| `2005` | Authorization failure | `3`, `10`, `368`, `4022`, `131005`, `131031`, and any other `200`–`299` |
| `2006` | User blocked business number | `4013`, `131050`, `900122` |
| `2007` | Message body exceeds maximum length | `132005` |
| `2009` | Message not delivered by operator | `130472`, `130497`, `131026` |
| `2011` | Authentication failure | `0`, `190` |
| `2015` | Throttled | `2`, `4`, `80007`, `130429`, `131016`, `131048`, `131056`, `131057`, `132069`, `134101`, `900117` |

**Send replies**

The send route answers WebEngage straight away, with a code and the matching HTTP status:

| Situation | WebEngage code | HTTP |
| --- | --- | --- |
| Accepted by OneXtel | `0` (`whatsapp_accepted`) | 200 |
| No API key | `2005` | 403 |
| OneXtel rejected the API key | `2011` | 401 |
| Payload `version` is not `1.0` | `2010` | 400 |
| Missing template data, recipient, business number or template name | `2002`, `2003`, `2004` or `2019` | 400 |
| OneXtel rejected the sender — for example a WABA ID in place of the business number | `2004` | 400 |
| OneXtel rejected the recipient | `2003` | 400 |
| Template or template-parameter problem | `2021` or `2022` | 400 |
| Rate limited | `2015` | 429 |
| Any other rejection | `9988` | 200 |

expiry, throttling or invalid number — and failing that by the report's delivery status:
`UNDELIV` becomes `2009`, anything else `9988`.

## Limitations

**All channels**

- **Inbound messages are not supported.** Customer replies do not appear in WebEngage. If
  two-way conversation matters, use the [WhatsApp](/api-reference/whatsapp/overview) or
  [RCS](/api-reference/rcs/overview) APIs directly.
- **Callbacks time out after 5 seconds** and are retried up to three times. If the connector
  does not acknowledge within that window, the callback is dropped rather than queued for later
  redelivery.

<Tabs>
<Tab title="WhatsApp">

- **Templates are duplicated, not synced.** A template created in WebEngage must manually
  replicate one approved in OneXtel. If either copy is edited, they drift apart.
- **Personalization variables only.** The connector supports personalization variables and no
  other variable form.
- **Variable ordering is assigned by the connector.** WebEngage does not send a variable index,
  so the connector assigns positions when building the OneXtel payload. Verify order-sensitive
  templates with a test send before going live.
- **Reports need WebEngage's WhatsApp token.** Until OneXtel has it, WhatsApp reports are held
  back.

</Tab>
<Tab title="RCS">

- **Templates are duplicated, not synced.** A template created in WebEngage must manually
  replicate one approved in OneXtel.
- **Only template names and parameters are passed** to OneXtel — the template body itself is
  resolved on the OneXtel side.
- **One Private RSP per message type**, because `campaigntype` is set on the configuration.

</Tab>
<Tab title="SMS">

- **India DLT traffic.** The Private SSP sends to OneXtel's India platform. For other countries,
  confirm with your OneXtel account team before you set up.
- **Delivery awaited is not reported.** WebEngage sees a message only once it has a final
  outcome.
- **The data centre comes from the callback URL.** Register a separate callback for each
  API key, with the right `in`, `ksa` or `us` suffix.

</Tab>
