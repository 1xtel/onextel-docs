The MoEngage connector adds WhatsApp and RCS as sendable channels inside MoEngage. You build
and segment campaigns exactly as you do today; the connector translates each campaign payload
into a OneXtel message and returns delivery status to MoEngage.

## Scope

<Tabs>
  <Tab title="WhatsApp">
    **Outbound**

    | Type | Supported |
    | --- | --- |
    | Text | ✅ |
    | Image | ✅ |
    | Video | ✅ |
    | Document | ✅ |
    | Location | ✅ |
    | Quick Reply buttons | ✅ |
    | Call-to-action buttons — static and dynamic | ✅ |

    **Inbound**

    Text replies and quick-reply button clicks are routed back to MoEngage.
  </Tab>
  <Tab title="RCS">
    **Outbound**

    | Type | Supported |
    | --- | --- |
    | Text | ✅ |
    | Rich Card | ✅ |
    | Rich Media | ✅ |
    | Suggestions | ✅ |
    | Webview | ✅ |
    | Audio | ❌ |
    | PDF / document | ❌ |

    Media URLs can be personalised from the MoEngage side, so a single template can render a
    different image or video per recipient.

    **Supported suggestion actions**

    `OPEN_URL`, `DIAL_PHONE`, `SHOW_LOCATION`, `QUERY_LOCATION`, `REQUEST_LOCATION`, and
    `CREATE_CAL_EVENT`.

    **SMS fallback**

    Supported. If RCS is not delivered, OneXtel retries over SMS — see
    [Set up RCS with SMS fallback](#set-up-rcs-with-sms-fallback).

    **Inbound**

    Suggestion interaction callbacks are returned. Inbound *messages* are not supported —
    see [Limitations](#limitations).
  </Tab>
</Tabs>

## Before you start

- A MoEngage account with the custom-provider channel available. RCS requires MoEngage to
  register OneXtel as a partner — raise this with your MoEngage account team before starting.
- A OneXtel account with the relevant channels enabled.
- Pre-approved templates in OneXtel. See
  [RCS templates](/api-reference/rcs/templates) and
  [WhatsApp templates](/api-reference/whatsapp/templates-create).
- For SMS fallback, an SMS sender ID and a DLT-approved SMS template registered against it in
  OneXtel.

### Connector endpoints

Every URL this connector uses sits on one host, `https://mo.onexaura.com`. Copy them from here
rather than retyping — MoEngage rejects nothing at save time, so a wrong path fails silently at
send.

| Purpose | Where you enter it | URL |
| --- | --- | --- |
| WhatsApp outbound | MoEngage sender — URL | `https://mo.onexaura.com/moengage/whatsapp/outbound` |
| WhatsApp inbound and button clicks | OneXtel callback — Callback URL | `https://mo.onexaura.com/moengage/whatsapp/inbound` |
| RCS outbound | MoEngage sender — API URL | `https://mo.onexaura.com/moengage/rcs/outbound` |
| RCS button clicks | OneXtel callback — Callback URL | `https://mo.onexaura.com/moengage/rcs/inbound` |
| SMS fallback outbound | MoEngage SMS provider — API URL | `https://mo.onexaura.com/moengage/sms` |
| SMS delivery reports | OneXtel callback — Callback URL, header `callback` | `https://mo.onexaura.com/moengage/sms/dlr` |

<Note>
The RCS and SMS **delivery notification** callbacks are the exception — those take the callback
URL MoEngage generates for you, not a OneXtel one. You copy that from the MoEngage sender screen
after saving it.
</Note>

<Warning>
This host has **no hyphen** — `onexaura.com`. OneXtel runs other connectors on similar-looking
hosts, so check it before saving.
</Warning>

## Set up WhatsApp

<Steps>
  <Step title="Get your OneXtel API key">
    Log in to OneXtel, go to the **API** section, and click **Show API Key**. If no key
    exists, click **Generate API Key**. Copy it — you need it in two later steps.
  </Step>
  <Step title="Add OneXtel as a sender in MoEngage">
    In MoEngage, go to **Settings → WhatsApp → Sender Configuration**. Select **OneXtel** from
    the left menu and click **+ Sender**, then enter:

    | Field | Value |
    | --- | --- |
    | URL | `https://mo.onexaura.com/moengage/whatsapp/outbound` |
    | WABA ID | From the OneXtel dashboard under **Channel → WhatsApp** |
    | Authorization | The API key from step 1 |
    | WABA Number | Your registered WhatsApp Business number |

    Click **Save**.
  </Step>
  <Step title="Configure the delivery report callback">
    In OneXtel, go to **Configuration → Add New Callback**. Give it a title, set **Channel**
    to `WhatsApp` and **Callback Format Type** to `MoEngage`, and select the same API key you
    used in MoEngage.

    Under **Request Configuration**, set **Type** to `Delivery Notification` and **HTTP
    Method** to `POST`. Paste the callback URL copied from your MoEngage dashboard, then save.
  </Step>
  <Step title="Configure the inbound callback">
    Add a second callback in OneXtel with the same channel, format type, and API key. Under
    **Request Configuration**, set **Type** to `Incoming` and **HTTP Method** to `POST`, and
    enter this URL:

    ```
    https://mo.onexaura.com/moengage/whatsapp/inbound
    ```

    In the **Header** section, add the key `callback_url` with your MoEngage DLR URL as the
    value. Save.
  </Step>
  <Step title="Configure the button-click callback">
    Repeat step 4 exactly, changing **Type** to `Button Click`. The URL, header key, and
    header value are all identical to the inbound callback.
  </Step>
</Steps>

## Set up RCS with SMS fallback

If an RCS message is not delivered, OneXtel can retry it over SMS. Fallback spans both
platforms: you create the fallback configuration and its DLR in OneXtel, then reference it from
MoEngage in two places — the RCS provider's Authorization value, and a separate SMS provider that
carries the actual fallback message. Fallback is optional; skip the steps marked
**(SMS fallback)** if you send RCS only.

Work through the parts in order.

| Part | What you do | Where |
| --- | --- | --- |
| [A](#part-a--create-the-rcs-sender-and-configure-sms) | Create the RCS sender and configure SMS fallback | OneXtel and MoEngage |
| [B](#part-b--create-templates-in-moengage) | Create templates | MoEngage |
| [C](#part-c--build-the-campaign) | Build the campaign and fill its variables | MoEngage |
| [D](#part-d--configure-the-callbacks-before-you-send) | Configure the callbacks | OneXtel |
| [E](#part-e--test-then-launch) | Test, then launch | Both |

### Part A — Create the RCS sender and configure SMS

<Steps>
  <Step title="Get your OneXtel API key">
    In the OneXtel portal, go to **API** and click **Show API Key**. If no key exists, click
    **Generate API Key**. Copy it — you need it twice below.

    <Frame caption="OneXtel API page">
      <img src="/images/plugins/moengage-rcs-apikey.png" alt="OneXtel API page with Show API and Generate API actions" />
    </Frame>
  </Step>

  <Step title="Find your RCS sender profile">
    In OneXtel, go to **Channels → RCS → Asset Management → Sender Profiles** and note the
    sender profile you want to send from, along with its message type.

    <Frame caption="RCS sender profiles in OneXtel">
      <img src="/images/plugins/onextel-rcs-sender-profiles.png" alt="OneXtel RCS Sender Profiles list showing each profile with its message type and status" />
    </Frame>
  </Step>

  <Step title="Add OneXtel as an RCS sender in MoEngage">
    In MoEngage, go to **Settings → SMS & RCS**, switch to the **RCS** tab, and click
    **+ Add RCS Sender**.

    <Frame caption="MoEngage SMS & RCS settings, RCS tab">
      <img src="/images/plugins/moengage-rcs-senders.png" alt="MoEngage SMS and RCS settings on the RCS tab with the Add RCS Sender action" />
    </Frame>

    Select **OneXtel** from the provider list.

    <Frame caption="Selecting OneXtel as the RCS provider">
      <img src="/images/plugins/moengage-rcs-provider.png" alt="MoEngage provider picker with OneXtel selected" />
    </Frame>
  </Step>

  <Step title="Enter the sender details">
    | Field | Value |
    | --- | --- |
    | Sender type | The message type this sender carries — **Transactional or Promotional** |
    | Sender Name | Your sender name, suffixed with the message type |
    | Sender ID | Your OneXtel sender profile, suffixed with the message type |
    | API URL | `https://mo.onexaura.com/moengage/rcs/outbound` |
    | Authorization | The API key from step 1 |

    <Frame caption="MoEngage RCS sender details. The callback URL shown is one region's host — yours may differ.">
      <img src="/images/plugins/moengage-rcs-senderform.png" alt="MoEngage RCS sender details form with sender type, name, ID, API URL and authorization" />
    </Frame>

    <Warning>
      MoEngage's **Sender type** list offers a third option, OTP. RCS supports Promotional and
      Transactional only — do not create an OTP sender.
    </Warning>

    Both **Sender Name** and **Sender ID** must carry the message type as an underscore suffix:

    ```
    Name_Promotional        SenderID_Promotional
    Name_Transactional      SenderID_Transactional
    ```

    <Note>
      **Create one sender per message type.** RCS templates in OneXtel are retrieved per message
      category, so you need a separate RCS sender for each message type you send — Promotional
      and Transactional. Each sender carries only the templates of its own type, which is why the
      type is encoded in the sender name.
    </Note>

    **Sender ID** accepts either a single sender profile or a **pool**. A pool groups several
    sender profiles so OneXtel can distribute traffic across them.

    <Warning>
      If you use a pool, **only templates assigned to that pool are available to it.** Choosing
      a template that belongs to a different profile leaves the send with nothing to resolve
      against. Check which templates the pool carries before you build the campaign — see
      [Sender profiles](/guides/rcs-platform/sender-profiles).
    </Warning>

    <Frame caption="A completed RCS sender. The Authorization value is blanked here — see the Authorization step below for what goes in it with SMS fallback. The api-01 callback host is region-specific; copy yours from your own screen.">
      <img src="/images/plugins/moengage-rcs-sender-filled.png" alt="Completed MoEngage RCS sender showing sender type, name, ID, the OneXtel outbound API URL, and the MoEngage callback URL" />
    </Frame>

    Save the sender. MoEngage then shows an **Incoming Messages & Delivery callback URL** —
    copy it, you paste it into OneXtel in
    [Part D](#part-d--configure-the-callbacks-before-you-send).

    <Warning>
      **Copy this URL from your own provider screen. Do not retype it, and do not take it from
      a screenshot or another account's setup.** The host depends on which MoEngage region your
      account runs in — `api-01`, `api-02`, and so on. The screenshots in this guide show one
      region's host, which will not be yours unless you happen to share it. A wrong region is
      accepted at save time and then silently never delivers a report.
    </Warning>
  </Step>

  <Step title="Create the fallback configuration in OneXtel (SMS fallback)">
    Go to the **Fallback** module, create a new configuration, give it a name, and select **SMS**
    as the fallback channel. Save.

    OneXtel generates a **Fallback ID** — copy it, you need it in the next step.

    <Frame caption="Creating an SMS fallback configuration in OneXtel">
      <img src="/images/plugins/moengage-fallback-config.png" alt="OneXtel Create Fallback Configuration dialog with a fallback name and one SMS fallback channel" />
    </Frame>
  </Step>

  <Step title="Extend the RCS sender Authorization value (SMS fallback)">
    Fallback is switched on by replacing the plain API key in the MoEngage RCS sender's
    **Authorization** field with four tilde-separated values:

    ```
    <apikey>~<ttl_Seconds>~<smsFallbackId>~<fallbackWaitTime_seconds>
    ```

    For example:

    ```
    QkLuVxXI~60s~0004d861-8a30-47c3-90d4-c06eb391ec3a~90
    ```

    | Value | What it is |
    | --- | --- |
    | `apikey` | The API key already configured for this provider |
    | `ttl_Seconds` | How long operators keep trying to deliver the RCS message, in seconds **with the `s` suffix** — for example `60s`. After this the message is marked failed |
    | `smsFallbackId` | The Fallback ID from the previous step |
    | `fallbackWaitTime_seconds` | How long OneXtel waits for an RCS delivery or failure report before sending the SMS, in seconds **as a plain number** — for example `90`. Defaults to `30` if missing or not numeric |

    <Note>
      You only need the extended value if you want SMS fallback. Without fallback, leave the
      field as the plain API key.
    </Note>

    <Warning>
      With fallback, all four values are required, in this order, separated by `~`. There is
      no separate fallback section in the MoEngage form — this single field is the whole
      configuration, so a missing value or a wrong separator disables fallback silently.
    </Warning>

    **Choosing TTL and wait time.** The two clocks start together at send time and do
    different jobs: TTL is the operator's deadline to deliver the RCS message, and wait time is
    how long OneXtel waits before it sends the SMS. Fallback fires when the wait time runs out
    without a delivery report.

    | Setting | Example | What happens |
    | --- | --- | --- |
    | TTL longer than wait time | `30s` TTL, `10` wait | The SMS goes out at 10 seconds if no delivery report has arrived, while the operator can still deliver the RCS message until 30 seconds. The recipient can get **both** |
    | TTL shorter than wait time | `30s` TTL, `60` wait | The RCS attempt stops at 30 seconds, but fallback still waits the full 60 seconds before the SMS goes out. No double delivery, but the recipient waits for the whole wait time |

    Keep TTL at or below the wait time. OneXtel's own campaign fallback sets TTL to 95% of the
    wait time for this reason — see [Fallback overview](/guides/omnichannel/fallback-overview).
  </Step>

  <Step title="Add an SMS custom service provider in MoEngage (SMS fallback)">
    Fallback sends the SMS through a separate MoEngage provider. Go to **Settings → SMS & RCS**,
    open the **SMS** tab, and click **Add Custom Service Provider**.

    Give it a name, and set **Sender Name** and **Sender ID** to match the values configured in
    OneXtel — the Sender ID must match exactly. Then set the API URL:

    ```
    https://mo.onexaura.com/moengage/sms
    ```

    <Frame caption="SMS custom service provider — the outbound URL must be on the same host as the RCS one">
      <img src="/images/plugins/moengage-sms-provider-url.png" alt="MoEngage custom SMS provider configuration with the OneXtel SMS outbound API URL highlighted" />
    </Frame>
  </Step>

  <Step title="Set the SMS provider request body (SMS fallback)">
    Set **Method** to `POST`, **Body type** to `Raw`, and paste:

    ```json
    {
      "key": "YOUR_API_KEY",
      "from": "YOUR_SENDER_ID",
      "to": "Moesms_destination",
      "body": "Moesms_message",
      "templateid": "Moesms_dltTemplateId",
      "entityid": "YOUR_DLT_ENTITY_ID"
    }
    ```

    The `Moesms_` values are MoEngage macros and must be left exactly as written — MoEngage
    substitutes them at send time. Replace `from` with your OneXtel sender ID, and `entityid`
    with your DLT entity ID.

    <Frame caption="Method POST, body type Raw, and the request body">
      <img src="/images/plugins/moengage-sms-provider-body.png" alt="MoEngage SMS provider API details with POST selected, Raw body type, and the JSON request body" />
    </Frame>

    Save.
  </Step>
</Steps>

### Part B — Create templates in MoEngage

Templates are built in OneXtel and recreated in MoEngage. Create the MoEngage template by
selecting the matching **Provider** and **Sender ID**, then copy the message body across from
the OneXtel dashboard.

<Warning>
**The two platforms use different placeholder syntax.** OneXtel wraps parameters in square
brackets; MoEngage wraps them in double curly braces. Copying a body across unchanged leaves the
placeholders unsubstituted, and the message goes out with literal `[custom_param]` text in it.
</Warning>

<CodeGroup>

```text OneXtel
Your money transfer of Rs. [custom_param] was successfully completed.
Transaction ID: [custom_param1]. Thank you for using our service.
```

```text MoEngage
Your money transfer of Rs. {{custom_param}} was successfully completed.
Transaction ID: {{custom_param1}}. Thank you for using our service.
```

</CodeGroup>

Apply the same conversion to every parameter in the template.

### Part C — Build the campaign

<Steps>
  <Step title="Create the campaign and select the template">
    Create or open the campaign in MoEngage and select your OneXtel RCS sender. Under
    **Select template**, choose the template you created in Part B. If the template has
    placeholders, MoEngage shows a field for each — fill them, using MoEngage personalization
    where the value varies per recipient. Media URLs can be personalised the same way.
  </Step>

  <Step title="Enable fallback on the campaign (SMS fallback)">
    Fallback is switched on per campaign, not globally. Tick **Use SMS as fallback**, then
    choose the SMS sender you created in Part A and enter the SMS template and message content.

    <Frame caption="Campaign content step with SMS fallback enabled">
      <img src="/images/plugins/moengage-campaign-fallback.png" alt="MoEngage campaign content step with Use SMS as fallback ticked and the SMS sender picker open" />
    </Frame>
  </Step>

  <Step title="Save without launching">
    Save the campaign, but do not launch it until the callbacks in Part D are in place —
    otherwise the delivery reports and button clicks from the first send never reach MoEngage.
  </Step>
</Steps>

### Part D — Configure the callbacks before you send

Before you launch, create the callbacks in OneXtel that carry delivery reports and button clicks
back to MoEngage. Each uses **Callback Format Type** `MoEngage` and the **same API key** you
entered in the MoEngage sender.

<Steps>
  <Step title="Configure the delivery report callback">
    In OneXtel, go to **Configuration → Add New Callback**. Give it a title, set **Channel** to
    `RCS` and **Callback Format Type** to `MoEngage`, and select the **same API key** you used
    in MoEngage.

    Under **Request Configuration**, set **Type** to `Delivery Notification` and **HTTP Method**
    to `POST`, then paste the callback URL you copied from MoEngage in Part A. Save.

    <Frame caption="Callback Configuration — Add New Callback">
      <img src="/images/plugins/moengage-rcs-callback-list.png" alt="OneXtel Config page on the Callback Configuration tab with the Add New Callback button highlighted" />
    </Frame>

    <Frame caption="RCS delivery notification callback with Callback Format set to MoEngage. The callback URL is the one copied from your own MoEngage sender screen.">
      <img src="/images/plugins/moengage-rcs-callback-dlr.png" alt="OneXtel Edit Callback screen with Channel RCS, Callback Format MoEngage, Type Delivery Notification and the MoEngage callback URL" />
    </Frame>
  </Step>

  <Step title="Configure the button-click callback">
    Add a second callback with the same channel, format type, and API key. Set **Type** to
    `Button click` and **HTTP Method** to `POST`, and enter this URL:

    ```
    https://mo.onexaura.com/moengage/rcs/inbound
    ```

    In the **Header** section, add the key `cbUrl` with your MoEngage DLR URL as the value —
    the same region-specific URL you copied from the sender screen, not one typed from this
    page.

    <Frame caption="Button click callback — note the cbUrl header at the bottom">
      <img src="/images/plugins/moengage-rcs-callback-buttonclick.png" alt="OneXtel Edit Callback screen with Type Button Click, the suggestion-clicked request preview, and a cbUrl header" />
    </Frame>
  </Step>

  <Step title="Configure the SMS delivery callback (SMS fallback)">
    Add a callback with **Channel** `SMS`, **Type** `Delivery Notification`, the **same API key**,
    **Callback Format** `MoEngage` and **HTTP Method** `POST`. Unlike the RCS delivery report,
    this one goes through the connector, which translates OneXtel's SMS receipt into MoEngage's
    format:

    | Field | Value |
    | --- | --- |
    | Callback URL | `https://mo.onexaura.com/moengage/sms/dlr` |
    | Header | key `callback`, value = the MoEngage DLR URL from the SMS provider screen |

    The header carries MoEngage's own DLR URL so one connector can serve several MoEngage
    accounts. `callback` is the header name every OneXtel connector uses for this; the older
    `cburl` is still accepted on this route.
  </Step>
</Steps>

<Warning>
The inbound header key differs by channel — WhatsApp uses `callback_url`, RCS uses `cbUrl`, and
the SMS delivery report uses `callback`. Using the wrong one silently breaks callback routing.
</Warning>

### Part E — Test, then launch

A fallback that is misconfigured does not stop the RCS send, so a successful campaign tells you
nothing about whether fallback works. Test each path separately before you launch:

<Steps>
  <Step title="Run a test message">
    Send the campaign as a test message to a device you control.
  </Step>
  <Step title="Confirm RCS delivery">
    The RCS message is delivered, and its delivery report reaches MoEngage.
  </Step>
  <Step title="Confirm SMS fallback">
    The SMS fallback actually fires and arrives.
  </Step>
  <Step title="Launch">
    Once both check out, launch the campaign to your full audience.
  </Step>
</Steps>

## Limitations

### Both channels

- **Template name and template ID must both match exactly** between MoEngage and OneXtel. A
  change to either on either side breaks the send.
- **Variable names must match the keys in the message payload.**
- **Callbacks time out after 5 seconds** and are retried up to three times. If MoEngage does
  not acknowledge within that window, the callback is dropped rather than queued for later
  redelivery.

### WhatsApp

- **Quick Reply or CTA, not both.** MoEngage does not support templates combining quick-reply
  and call-to-action buttons.
- **Static button data is not included** in the MoEngage payload.
- **Click events are not available.** MoEngage exposes no API to receive them, so link clicks
  cannot be written back into MoEngage reporting. Use
  [OneXtel reporting](/guides/rcs-platform/reports-detail) for click data.

### RCS

- **Inbound messages are not supported** by MoEngage. Suggestion interaction callbacks are
  returned, but free-form customer replies cannot be surfaced in MoEngage.
- **Only template names and parameters are passed** to OneXtel — the template body itself is
  resolved on the OneXtel side.
- **Audio and PDF are not supported** by MoEngage on RCS.
- **Carousel templates are not yet available** — see
  [Coming soon](/plugins/overview#coming-soon).

## Get support

If a campaign does not behave as this page describes, email
[omni.tech@onextel.com](mailto:omni.tech@onextel.com) with the plugin name (MoEngage), the
channel, and what you saw. To let OneXtel see exactly what MoEngage sent and what OneXtel
answered:

<Steps>
  <Step title="Ask for the logging endpoint">
    Support will give you a logging version of the connector URL for the affected channel.
  </Step>
  <Step title="Point the sender at it">
    In MoEngage, open the OneXtel sender and replace the **API URL** with the logging URL.
    Nothing else changes.
  </Step>
  <Step title="Run the campaign again">
    Send the campaign to a small test audience.
  </Step>
  <Step title="Share the campaign ID">
    Reply to support with the MoEngage campaign ID. OneXtel matches it against the logged
    requests and responses and comes back with the exact cause.
  </Step>
</Steps>

Switch the API URL back to the normal connector URL once the issue is closed.
