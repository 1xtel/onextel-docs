The MoEngage connector adds WhatsApp and RCS as sendable channels inside MoEngage. You build
and segment campaigns exactly as you do today; the connector translates each campaign payload
into a OneXtel message and returns delivery status to MoEngage.

## Scope

<Tabs>
  <Tab title="WhatsApp">
    **Outbound**

    | Type | Supported |
    | --- | --- |
    | Text | ✅ |
    | Image | ✅ |
    | Video | ✅ |
    | Document | ✅ |
    | Location | ✅ |
    | Quick Reply buttons | ✅ |
    | Call-to-action buttons — static and dynamic | ✅ |

    **Inbound**

    Text replies and quick-reply button clicks are routed back to MoEngage.
  </Tab>
  <Tab title="RCS">
    **Outbound**

    | Type | Supported |
    | --- | --- |
    | Text | ✅ |
    | Rich Card | ✅ |
    | Rich Media | ✅ |
    | Suggestions | ✅ |

    **Supported suggestion actions**

    `OPEN_URL`, `DIAL_PHONE`, `SHOW_LOCATION`, `QUERY_LOCATION`, `REQUEST_LOCATION`, and
    `CREATE_CAL_EVENT`.

    **Inbound**

    Suggestion interaction callbacks are returned. Inbound *messages* are not supported —
    see [Limitations](#limitations).
  </Tab>
</Tabs>

## Set up WhatsApp

<Steps>
  <Step title="Get your OneXtel API key">
    Log in to OneXtel, go to the **API** section, and click **Show API Key**. If no key
    exists, click **Generate API Key**. Copy it — you need it in two later steps.
  </Step>
  <Step title="Add OneXtel as a sender in MoEngage">
    In MoEngage, go to **Settings → WhatsApp → Sender Configuration**. Select **OneXtel** from
    the left menu and click **+ Sender**, then enter:

    | Field | Value |
    | --- | --- |
    | URL | `https://mo.onexaura.com/moengage/whatsapp/outbound` |
    | WABA ID | From the OneXtel dashboard under **Channel → WhatsApp** |
    | Authorization | The API key from step 1 |
    | WABA Number | Your registered WhatsApp Business number |

    Click **Save**.
  </Step>
  <Step title="Configure the delivery report callback">
    In OneXtel, go to **Configuration → Add New Callback**. Give it a title, set **Channel**
    to `WhatsApp` and **Callback Format Type** to `MoEngage`, and select the same API key you
    used in MoEngage.

    Under **Request Configuration**, set **Type** to `Delivery Notification` and **HTTP
    Method** to `POST`. Paste the callback URL copied from your MoEngage dashboard, then save.
  </Step>
  <Step title="Configure the inbound callback">
    Add a second callback in OneXtel with the same channel, format type, and API key. Under
    **Request Configuration**, set **Type** to `Incoming` and **HTTP Method** to `POST`, and
    enter this URL:

    ```
    https://mo.onexaura.com/moengage/whatsapp/inbound
    ```

    In the **Header** section, add the key `callback_url` with your MoEngage DLR URL as the
    value. Save.
  </Step>
  <Step title="Configure the button-click callback">
    Repeat step 4 exactly, changing **Type** to `Button Click`. The URL, header key, and
    header value are all identical to the inbound callback.
  </Step>
</Steps>

## Set up RCS

<Steps>
  <Step title="Get your OneXtel API key">
    In the OneXtel portal, go to **API** and click **Show API Key**. If no key exists, click
    **Generate API Key**. Copy it — you need it twice below.

    <Frame caption="OneXtel API page">
      <img src="/images/plugins/moengage-rcs-apikey.png" alt="OneXtel API page with Show API and Generate API actions" />
    </Frame>
  </Step>

  <Step title="Find your RCS sender profile">
    In OneXtel, go to **Channels → RCS → Asset Management → Sender Profiles** and note the
    sender profile you want to send from, along with its message type.

    <Frame caption="RCS sender profiles in OneXtel">
      <img src="/images/plugins/onextel-rcs-sender-profiles.png" alt="OneXtel RCS Sender Profiles list showing each profile with its message type and status" />
    </Frame>
  </Step>

  <Step title="Add OneXtel as an RCS sender in MoEngage">
    In MoEngage, go to **Settings → SMS & RCS**, switch to the **RCS** tab, and click
    **+ Add RCS Sender**.

    <Frame caption="MoEngage SMS & RCS settings, RCS tab">
      <img src="/images/plugins/moengage-rcs-senders.png" alt="MoEngage SMS and RCS settings on the RCS tab with the Add RCS Sender action" />
    </Frame>

    Select **OneXtel** from the provider list.

    <Frame caption="Selecting OneXtel as the RCS provider">
      <img src="/images/plugins/moengage-rcs-provider.png" alt="MoEngage provider picker with OneXtel selected" />
    </Frame>
  </Step>

  <Step title="Enter the sender details">
    | Field | Value |
    | --- | --- |
    | Sender type | The message type this sender carries — **Transactional or Promotional** |
    | Sender Name | Your sender name, suffixed with the message type |
    | Sender ID | Your OneXtel sender profile, suffixed with the message type |
    | API URL | `https://mo.onexaura.com/moengage/rcs/outbound` |
    | Authorization | The API key from step 1 |

    <Frame caption="MoEngage RCS sender details">
      <img src="/images/plugins/moengage-rcs-senderform.png" alt="MoEngage RCS sender details form with sender type, name, ID, API URL and authorization" />
    </Frame>

    <Warning>
      MoEngage's **Sender type** list offers a third option, OTP. RCS supports Promotional and
      Transactional only — do not create an OTP sender.
    </Warning>

    Both **Sender Name** and **Sender ID** must carry the message type as an underscore suffix:

    ```
    Name_Promotional        SenderID_Promotional
    Name_Transactional      SenderID_Transactional
    ```

    Save the sender. MoEngage then shows an **Incoming Messages & Delivery callback URL** —
    copy it, you need it in the next step.
  </Step>

  <Step title="Configure the delivery report callback in OneXtel">
    In OneXtel, go to **Configuration → Add New Callback**. Give it a title, set **Channel** to
    `RCS` and **Callback Format Type** to `MoEngage`, and select the **same API key** you used
    in MoEngage.

    Under **Request Configuration**, set **Type** to `Delivery Notification` and **HTTP Method**
    to `POST`, then paste the callback URL you copied from MoEngage. Save.

    <Frame caption="Callback Configuration — Add New Callback">
      <img src="/images/plugins/moengage-rcs-callback-list.png" alt="OneXtel Config page on the Callback Configuration tab with the Add New Callback button highlighted" />
    </Frame>

    <Frame caption="RCS delivery notification callback with Callback Format set to MoEngage">
      <img src="/images/plugins/moengage-rcs-callback-dlr.png" alt="OneXtel Edit Callback screen with Channel RCS, Callback Format MoEngage, Type Delivery Notification and the MoEngage callback URL" />
    </Frame>
  </Step>

  <Step title="Configure the button-click callback in OneXtel">
    Add a second callback with the same channel, format type, and API key. Set **Type** to
    `Button click` and **HTTP Method** to `POST`, and enter this URL:

    ```
    https://mo.onexaura.com/moengage/rcs/inbound
    ```

    In the **Header** section, add the key `cbUrl` with your MoEngage DLR URL as the value.

    <Frame caption="Button click callback — note the cbUrl header at the bottom">
      <img src="/images/plugins/moengage-rcs-callback-buttonclick.png" alt="OneXtel Edit Callback screen with Type Button Click, the suggestion-clicked request preview, and a cbUrl header" />
    </Frame>
  </Step>
</Steps>

<Warning>
The inbound header key differs by channel — WhatsApp uses `callback_url`, RCS uses `cbUrl`.
Using the wrong one silently breaks callback routing.
</Warning>

## One sender per message type

RCS templates in OneXtel are retrieved per message category, so you need **a separate RCS
sender for each message type** you send — Promotional and Transactional. Each sender carries
only the templates of its own type, which is why the type is encoded in the sender name.

## Requirements

- A MoEngage account with the custom-provider channel available. RCS requires MoEngage to
  register OneXtel as a partner — raise this with your MoEngage account team before starting.
- A OneXtel account with the relevant channels enabled.
- Pre-approved templates in OneXtel. See
  [RCS templates](/api-reference/rcs/templates) and
  [WhatsApp templates](/api-reference/whatsapp/templates-create).

## Limitations

### Both channels

- **Template names must match exactly** between MoEngage and OneXtel — templates are resolved
  by name, not ID. A rename on either side breaks the send.
- **Variable names must match the keys in the message payload.**
- **Callbacks time out after 5 seconds** and are retried up to three times. If MoEngage does
  not acknowledge within that window, the callback is dropped rather than queued for later
  redelivery.

### WhatsApp

- **Quick Reply or CTA, not both.** MoEngage does not support templates combining quick-reply
  and call-to-action buttons.
- **Static button data is not included** in the MoEngage payload.
- **Click events are not available.** MoEngage exposes no API to receive them, so link clicks
  cannot be written back into MoEngage reporting. Use
  [OneXtel reporting](/guides/rcs-platform/reports-detail) for click data.

### RCS

- **Inbound messages are not supported** by MoEngage. Suggestion interaction callbacks are
  returned, but free-form customer replies cannot be surfaced in MoEngage.
- **Only template names and parameters are passed** to OneXtel — the template body itself is
  resolved on the OneXtel side.
- **Carousel templates and SMS fallback are not yet available.** Both are in testing — see
  [Coming soon](/plugins/overview#coming-soon).
