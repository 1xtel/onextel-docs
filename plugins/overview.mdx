OneXtel plugins let your team send messages through OneXtel from the tools they already work
in — your CRM, your marketing automation platform, your storefront. Campaigns are built and
triggered where they always were; OneXtel handles template delivery, carrier routing, delivery
reports, and inbound replies underneath.

## What each plugin covers

Every plugin covers the same four areas. What differs is how much of each the host platform
itself can express — a limitation of the platform, not of OneXtel.

  <Card title="Template handling" icon="table-columns">

## Common requirements

Whichever plugin you use:

- **An active OneXtel account** with an API key for the channels you intend to send on. Every
  setup starts by copying your API key from **API → Show API Key** in the OneXtel portal.
- **Approved templates.** WhatsApp and RCS templates must be approved in OneXtel before a
  campaign can use them, and SMS templates must be DLT-registered where applicable. See
  [WhatsApp templates](/api-reference/whatsapp/templates-create) and
  [RCS templates](/api-reference/rcs/templates).
- **A registered sender.** A WhatsApp Business number, an
  [RCS agent](/guides/rcs-platform/sender-profiles), or an
  [SMS sender ID](/guides/sms/sender-id), depending on channel.
- **Matching template names.** Several platforms match templates by name rather than ID, so
  the name in the host platform must match the name in OneXtel exactly.
- **A callback configured in OneXtel.** Delivery reports and inbound messages only reach the
  host platform once the corresponding callback is registered against your API key, under
  **Configuration → Add New Callback** in the portal.

## Message categories

Templates are approved by category, and plugins send on these:

| Channel | Categories |
| --- | --- |
| RCS | Promotional, Transactional |
| WhatsApp | Marketing, Utility |

Because templates are fetched per category, most platforms need a separate sender or channel
configuration for each category you send on. The per-plugin pages show how each one expresses
this.

</Note>

## Choosing between a plugin and the API

Use a **plugin** when campaigns are already built and triggered in the host platform, and you
want messaging to live alongside the rest of that platform's reporting.

Use the [API](/api-reference/whatsapp/overview) directly when you need message types or
controls the host platform cannot express — every plugin is limited by what its platform's
campaign builder supports, and those limits are listed on each page.
