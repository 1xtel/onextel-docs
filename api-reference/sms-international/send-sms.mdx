## Endpoint

```text
POST https://api.int.onexglobal.io/api/jsmslist
```

<ParamField header="Content-Type" type="string" required>
  `application/json`
</ParamField>

## Single submission

Send one SMS by putting one object in the `listsms` array.

```bash
curl --location 'https://api.int.onexglobal.io/api/jsmslist' \
--header 'Content-Type: application/json' \
--data '{
  "key": "XXXXXX",
  "listsms": [
    {
      "from": "Verify",
      "to": "mobile number",
      "body": "Your verification code is 1234",
      "clientsmsid": "123456789"
    }
  ]
}'
```

## Multiple submission

Send several SMS in one request by adding one object per message to the `listsms` array.

```bash
curl --location 'https://api.int.onexglobal.io/api/jsmslist' \
--header 'Content-Type: application/json' \
--data '{
  "key": "XXXXXX",
  "listsms": [
    {
      "from": "9599750774",
      "to": "9898989898",
      "body": "Your verification otp is 192031",
      "clientsmsid": "123456789"
    },
    {
      "from": "9599750774",
      "to": "9898989898",
      "body": "Your verification otp is 192031",
      "clientsmsid": "123456789"
    },
    {
      "from": "9599750774",
      "to": "9898989898",
      "body": "Your verification otp is 192031",
      "clientsmsid": "123456789"
    },
    {
      "from": "9599750774",
      "to": "9898989898",
      "body": "Your verification otp is 192031",
      "clientsmsid": "123456789"
    }
  ]
}'
```

## Request parameters

The request body must be JSON and include the parameters below.

<ParamField body="key" type="string" required>
  The API key assigned to you for authentication. Generate it in the portal under **API**. See [API keys](/guides/sms-international/api-keys).
</ParamField>

<ParamField body="listsms" type="array">
  A list of one or more SMS message objects to send.
</ParamField>

### `listsms` object

Each object in the `listsms` array is one SMS message.

<ParamField body="from" type="string" required>
  The sender ID or name that appears as the message originator.
</ParamField>

<ParamField body="to" type="string" required>
  The recipient's mobile number, including the country code. For example, `918872725225`.
</ParamField>

<ParamField body="body" type="string" required>
  The text content of the SMS.
</ParamField>

<ParamField body="clientsmsid" type="string">
  Your own unique identifier for tracking the message. Returned as `CLIENTMSID` on the [delivery receipt](/api-reference/sms-international/dlr-callback).
</ParamField>

## Response

The API returns a JSON response under `smslist` → `sms`, with one record per submitted message showing its processing status.

<CodeGroup>

```json Success
{
  "smslist": {
    "sms": [
      {
        "reason": "success",
        "code": 0,
        "messageid": "36NHM9t0WzRM9VtK4n7iI7Yd2Da",
        "messagepartids": [],
        "mobileno": "971502829916",
        "status": "success"
      }
    ]
  }
}
```

```json Failed
{
  "smslist": {
    "sms": [
      {
        "reason": "invalid mobileno",
        "code": 700,
        "mobileno": "9715028",
        "clientsmsid": "123456789",
        "status": "fail"
      }
    ]
  }
}
```

</CodeGroup>

### Success fields

<ResponseField name="reason" type="string">
  Status description of the submission.
</ResponseField>

<ResponseField name="code" type="integer">
  Numeric response code. `0` means success.
</ResponseField>

<ResponseField name="messageid" type="string">
  Unique internal message identifier. The same value arrives as `MSGID` on the delivery receipt.
</ResponseField>

<ResponseField name="messagepartids" type="array">
  IDs for the parts of a multipart message. Empty for a single-part message.
</ResponseField>

<ResponseField name="mobileno" type="string">
  Destination mobile number.
</ResponseField>

<ResponseField name="status" type="string">
  Submission status: `success`.
</ResponseField>

### Failure fields

<ResponseField name="reason" type="string">
  Cause of the submission failure.
</ResponseField>

<ResponseField name="code" type="integer">
  Error code. `700` means the mobile number format is invalid.
</ResponseField>

<ResponseField name="mobileno" type="string">
  The mobile number you provided.
</ResponseField>

<ResponseField name="clientsmsid" type="string">
  The `clientsmsid` you passed, for reference.
</ResponseField>

<ResponseField name="status" type="string">
  Submission status: `fail`.
</ResponseField>

## Submission codes

| Code | Description |
| --- | --- |
| `0` | Submission successful |
| `700` | Invalid mobile number |

<Note>
  A `0` means OneXtel accepted the message for delivery, not that it was delivered. The delivery outcome arrives later on the [DLR callback](/api-reference/sms-international/dlr-callback).
</Note>
