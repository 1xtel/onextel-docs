---
title: "Send Non-Template Messages"
description: "Send free-form RCS plain text, rich card standalone, and rich card carousel messages via the Send Message API."
---

Send free-form (non-template) RCS content through the same Send Message endpoint used by all
OnexAura channels. Non-template messages build the content directly in the request body,
instead of referencing a pre-approved `templateCode`.

## Endpoint

```
POST https://api.onexaura.com/oapi/send_sms
```

<ParamField header="apikey" type="string" required>
  Your OneXtel API key.
</ParamField>

<ParamField header="Content-Type" type="string" required>
  Must be `application/json`.
</ParamField>

## Request structure

Every request wraps one or more message objects in an `rcs` array:

```json
{
  "rcs": [ { /* messageObject */ } ],
  "prefix": "+91",
  "urlShortener": { /* optional */ }
}
```

<ParamField body="rcs" type="array" required>
  Array of RCS message objects to send.
</ParamField>

<ParamField body="prefix" type="string">
  Country code prefix (e.g. `+91`) applied to recipient numbers that don't already include one.
</ParamField>

<ParamField body="urlShortener" type="object">
  Optional. Shortens and tracks links inside the message. See [URL shortener](#url-shortener).
</ParamField>

### Message object (`rcs[]`)

<ParamField body="messageType" type="string" required>
  Message category: `Promotional`, `Transactional`, or `OTP`.
</ParamField>

<ParamField body="recipient" type="string" required>
  Recipient phone number, without the `prefix`.
</ParamField>

<ParamField body="sender" type="string" required>
  RCS sender/bot ID.
</ParamField>

<ParamField body="contentMessage" type="object" required>
  Holds the message body — one of `text` or `richCard` for non-template messages.
</ParamField>

<ParamField body="ttl" type="string">
  Time-to-live for the message (e.g. `"1200s"`). Provide only one of `ttl` or `expireTime`.
</ParamField>

<ParamField body="expireTime" type="string">
  Absolute expiry time in UTC/Zulu format (e.g. `"2024-10-02T15:01:23Z"`). Provide only one of
  `ttl` or `expireTime`.
</ParamField>

<ParamField body="custref1" type="string">
  Optional custom reference field. Up to `custref6` is accepted for plain text messages, and
  `custref1`–`custref5` for rich card messages.
</ParamField>

<Note>
`ttl` and `expireTime` are mutually exclusive — provide at most one.
</Note>

## Message types

<Tabs>
  <Tab title="Plain Text">
    The simplest non-template message: a `text` field inside `contentMessage`.

    <ParamField body="contentMessage.text" type="string" required>
      The plain text content of the message.
    </ParamField>

    <ParamField body="contentMessage.fileUrl" type="string">
      Optional URL of a file to attach alongside the text.
    </ParamField>

    ```json Request
    {
      "rcs": [
        {
          "messageType": "Promotional",
          "recipient": "919999999999",
          "sender": "your_rcs_sender",
          "contentMessage": {
            "text": "Your OTP is 482913"
          },
          "custref1": "",
          "custref2": "",
          "custref3": "",
          "custref4": "",
          "custref5": "",
          "custref6": ""
        }
      ],
      "prefix": "+91"
    }
    ```

    ```bash cURL
    curl --location 'https://api.onexaura.com/oapi/send_sms' \
    --header 'apikey: YOUR_API_KEY' \
    --header 'Content-Type: application/json' \
    --data '{
      "rcs": [
        {
          "messageType": "Promotional",
          "recipient": "919999999999",
          "sender": "your_rcs_sender",
          "contentMessage": {
            "text": "Your OTP is 482913"
          }
        }
      ],
      "prefix": "+91"
    }'
    ```

    <Note>
    A plain text message can also carry a `ttl` (e.g. `"1200s"`) alongside `contentMessage.text`
    to set an expiry — provide only one of `ttl` or `expireTime`.
    </Note>
  </Tab>

    <ParamField body="contentMessage.richCard.standaloneCard.cardOrientation" type="string" required>

## Suggestions

`cardContent.suggestions` (rich card standalone) accepts a list of quick-reply or action chips.

**Reply suggestion:**

```json
{
  "reply": {
    "text": "Suggestion #1",
    "postbackData": "suggestion_1"
  }
}
```

**Action suggestion (Open URL):**

```json
{
  "action": {
    "text": "Shop Now",
    "postbackData": "shop_now",
    "openUrlAction": {
      "url": "https://example.com/shop",
      "application": "BROWSER",
      "webviewViewMode": "FULL"
    }
  }
}
```

| Field | Values | Description |
| --- | --- | --- |
| `application` | `BROWSER` (default), `WEBVIEW` | How to open the URL. |
| `webviewViewMode` | `FULL` (default), `TALL`, `HALF` | Webview size, only applicable when `application` is `WEBVIEW`. |

## URL shortener

Set `urlShortener` at the top level (alongside `rcs` and `prefix`) to shorten and optionally
track links referenced in the message.

<ParamField body="urlShortener.flag" type="integer">
  `1` to enable URL shortening, `0` to disable.
</ParamField>

<ParamField body="urlShortener.urlDetails" type="array">
  Array of URLs to shorten.
</ParamField>

<ParamField body="urlShortener.urlDetails[].longUrl" type="string" required>
  The original full URL to shorten.
</ParamField>

<ParamField body="urlShortener.urlDetails[].senderId" type="string">
  Sender ID or bot ID associated with the message (matches your RCS sender).
</ParamField>

<ParamField body="urlShortener.urlDetails[].domain" type="string">
  Custom domain to use for the shortened link.
</ParamField>

<ParamField body="urlShortener.urlDetails[].track_user" type="boolean">
  Whether to enable user-level click tracking. Default: disabled.
</ParamField>

<ParamField body="urlShortener.urlDetails[].expiry" type="string">
  Optional expiry for the shortened URL.
</ParamField>

## Response

```json Response
[
  {
    "messageId": "33mXmXf0myfFe7lA1QpPcDJcVaH",
    "code": 200,
    "status": "success"
  }
]
```

<ResponseField name="messageId" type="string">
  Unique identifier for the submitted message. Use it to correlate delivery reports.
</ResponseField>

<ResponseField name="code" type="integer">
  Result code. `200` indicates the message was accepted.
</ResponseField>

<ResponseField name="status" type="string">
  Result status, e.g. `success`.
</ResponseField>

<Note>
Depending on the TUC (tenant/use-case) configuration, additional fields such as `recipient`,
`sender`, and `custref1`–`custref5` may be dynamically added to each response object.
</Note>
